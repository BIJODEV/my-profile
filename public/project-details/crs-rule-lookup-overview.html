🔍 CRS Rule Lookup Tool

A security analyst's workbench for decoding Cloudflare WAF firewall events against the OWASP Core Rule Set — bridging rule IDs to human-readable context, live regex highlighting, and encrypted payload decryption.

React + Vite OWASP CRS FastAPI / Python Cloudflare WAF Google OAuth

What Is This?

When Cloudflare's WAF blocks a web request, it logs an opaque internal UUID and a numeric CRS ID. Out-of-the-box these identifiers give you very little actionable information — you can't tell which attack pattern triggered the block, what part of the request matched, or why a legitimate request might have been flagged.

This project solves that problem end-to-end: it parses the entire OWASP Core Rule Set source into a structured database, maps every Cloudflare UUID back to its CRS counterpart, then provides a browser-based UI where a security analyst can paste rule IDs (or upload a raw Cloudflare security event JSON), immediately see the rule details, and — when an AES-GCM "Payload Log Key" is provided — decrypt and display the exact matched request fragment with the triggering regex highlighted inline.

Three Sub-Projects

1 · coreruleset/
OWASP CRS v4 (upstream clone) + custom parse scripts

The full OWASP Core Rule Set source tree. Two custom scripts were added on top: parse-crs.js (Node) and parse_crs.py (Python root-level) walk every .conf file, normalise line continuations, extract rule ID, message, pattern, phase, severity, tags, and paranoia level, and emit a structured JSON database.

2 · crs-rule-lookup/
React 19 · Vite 7 · Tailwind CSS 4 · pcre-to-regexp

The analyst-facing single-page app. Accepts manual CRS/CF ID searches or a full Cloudflare security event JSON upload. Decodes, maps, and renders rule details with live PCRE regex highlighting over the matched payload. Protected by Google Sign-In OAuth with an allow-list of authorised emails.

3 · cloudflare-decrypt-api/
Python 3.9 · FastAPI · uvicorn · pyhpke · cryptography

A lightweight local microservice that wraps Cloudflare's matched-data-cli binary. The React UI posts the encrypted payload blob and the analyst's private key; the API decrypts it via HPKE and returns plaintext. Deployed to Render.com for remote access.

Data Pipeline — How the Knowledge Base Is Built

1
Parse the OWASP Core Rule Set

parse_crs.py reads all 48 .conf files under coreruleset/rules/. It merges line continuations, extracts every SecRule directive, and serialises id, message, pattern, operator type, file name, phase, severity, tags, and paranoia level into a structured JSON array.

2
Map Cloudflare UUIDs to CRS IDs

cfrules.json is a hand-curated (or separately sourced) list of 179 Cloudflare-internal UUID → CRS numeric ID mappings with human messages. mergeRules.js joins this list against the parsed CRS data to produce updatedRules.json, the single source of truth bundled into the UI.

3
Bundle into the React App

Vite inlines updatedRules.json at build time. No backend is needed for lookups — the entire 179-rule map ships with the JS bundle. Only decryption requires the FastAPI microservice.

4
Decrypt Encrypted Matched Data (optional)

Cloudflare's "Payload Logging" feature encrypts matched request fragments using HPKE (Hybrid Public Key Encryption). When the analyst provides their private key, the React UI calls the FastAPI /decrypt endpoint, which shells out to Cloudflare's matched-data-cli binary and returns the plaintext JSON.

UI Features

🔎
Dual ID Search
Search by numeric CRS ID (e.g. 942100) or Cloudflare UUID — both resolve to the same rule record. Comma-separated batch input supported.
📂
Security Event JSON Upload
Upload a raw Cloudflare Firewall Event JSON export. The app auto-extracts triggered rule IDs from the score_rules metadata field.
🔐
HPKE Payload Decryption
If encrypted_matched_data is present in the event, enter the AES-GCM private key and the app decrypts + displays the exact matched request fragments per variable location.
🌈
Live Regex Highlighting
The CRS PCRE pattern for each triggered rule is compiled (with fallback via pcre-to-regexp) and run against the decrypted payload. Matches are highlighted yellow inline.
📋
One-Click Pattern Copy
Each result row shows the full ModSecurity regex pattern with a clipboard copy button — useful for reproducing the detection in test tools.
⬇
Download Results as JSON
Any search result set can be exported as a structured JSON file for sharing or further processing in pipelines.
🔒
Google OAuth Access Gate
The app renders a blurred preview behind a sign-in overlay. Only email addresses on a hard-coded allow-list can authenticate and use the tool.
⚠️
Graceful Fallback Highlighting
When a CRS PCRE pattern cannot be fully transpiled to JavaScript regex, the tool falls back to keyword-based highlighting and marks the row with a warning icon.

Who Is This For & Typical Workflow

This tool targets security engineers and WAF operators who work with Cloudflare's Managed Ruleset (which is built on the OWASP CRS) and need to triage WAF block events quickly.

Typical workflow:

  1. A Cloudflare security event fires — you receive a JSON export with Cloudflare UUIDs and an encrypted payload blob.
  2. Upload the JSON to the tool.
  3. The tool resolves all triggered UUIDs → CRS rule IDs → rule messages + patterns.
  4. Enter your Payload Log private key → the exact matched request fragments are decrypted and displayed.
  5. The triggering PCRE regex is compiled and run over the decrypted text — matching portions are highlighted.
  6. You can now see exactly which part of the request triggered which rule and why — enabling fast triage between true positives and false positives.
⚠️ The tool is intentionally gated behind Google OAuth because it handles sensitive payload data. Only a small team of trusted emails can access it. Decryption happens server-side on Render.com and the private key is never persisted.
