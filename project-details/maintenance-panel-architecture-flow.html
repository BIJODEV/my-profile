Backend Architecture Overview

This diagram traces two independent paths: a visitor's live request, and an operator's scheduling action — sharing one Worker, one D1 database, and one edge rule, but never crossing each other directly.

💡 Click any node above to learn its role.

Key components
  • Edge UI: a status/scheduling dashboard, served as static assets
  • Edge Worker: serves the UI and REST API, and configures the rule below — never sits in the visitor's request path
  • D1 Database: durable state — active windows and the append-only audit log
 
  • Snippet Rule: the deployed edge rule a visitor's request actually hits, configured ahead of time via the Rulesets API
  • Origin / Storefront: the customer's real site — what visitors reach whenever no window is active
  • Cron Trigger: sweeps every minute to activate and retract windows automatically
Data flow

A visitor's request is matched against the Snippet Rule at the edge — if a window is active, they get an instant 503, before ever reaching origin; otherwise it's forwarded through, unmodified. Separately, the operator's UI talks to the Worker over a REST API to schedule windows, which the Worker persists in D1 and mirrors to the edge rule via the Rulesets API. Every minute, the Cron Trigger sweeps D1 and flips that same rule on or off automatically — no new infrastructure to run, self-scheduling and self-expiring.
