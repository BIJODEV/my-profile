01 — Executive Summary

FlareSight is a purpose-built, enterprise-grade analytics and command center that sits on top of our CDN and WAF infrastructure — currently supporting both Cloudflare and IBM Cloud Internet Services (CIS). Rather than requiring engineers to manually comb through raw API logs across hundreds of zones, FlareSight aggregates, processes, and visualises all traffic, security, performance, and compliance data in a single, real-time dashboard.

In one sentence: FlareSight turns raw CDN telemetry from 100+ internet-facing zones into actionable executive intelligence — protecting revenue, reducing cost, and proving security posture to auditors, all without writing a single API query.
02 — The Problem Being Solved
Managing a large portfolio of internet-facing zones without consolidated visibility creates four compounding risks:

🔴 Operational Blind Spots

Engineers have no single view across all zones. Security incidents, configuration drift, or traffic anomalies go undetected until they cause outages or breaches. Manual querying of the Cloudflare/CIS GraphQL API for even one zone takes significant expertise and time.

🟠 Compliance Drift

With 100+ zones spanning production, staging, dev, and integration environments, keeping security settings (TLS grade, HSTS, WAF, Bot Fight Mode) consistent and compliant is impossible to audit manually. A single misconfigured zone is a compliance and audit liability.

🟣 Hidden Infrastructure Costs

Without visibility into per-zone cache hit rates, teams cannot identify which zones are driving up egress bandwidth costs. Poorly tuned caching can silently cost tens of thousands of dollars per year in unnecessary origin egress fees.

🔴 Threat Intelligence Gaps

Raw WAF event logs expose thousands of cryptic rule IDs with no human-readable context. Security teams cannot distinguish a coordinated SQL injection campaign from normal noise, making prioritisation and response slow and error-prone.

04 — Key Differentiator: Multi-Provider Architecture
A critical architectural decision distinguishes FlareSight from any off-the-shelf Cloudflare dashboard: it supports both Cloudflare and IBM Cloud Internet Services (CIS) through a unified provider abstraction layer.

Single Dashboard, Two Providers

All seven capability modules (traffic, portfolio, performance, compliance, security, threats, deep dive) work identically regardless of whether the backend is Cloudflare or IBM CIS. Operators switch providers from a single dropdown — no reconfiguration required.

Strategic Flexibility

This means management can evaluate, compare, or migrate between CDN providers without losing analytical continuity. No vendor lock-in on the visibility layer. IBM CIS instances (DEV, STAGE, PROD) can each be independently monitored from the same UI.

06 — How It Works (Technical Architecture)
🔌
Data Ingestion — Cloudflare & IBM CIS APIs

FlareSight connects to the Cloudflare GraphQL Analytics API or IBM CIS REST API using a read-only analytics token. It fetches zones, traffic, security events, settings, and performance data in parallel batched queries — no data is stored server-side.

⚙️
Processing Layer — Smart Data Processors

Eight specialised processor modules (traffic, security, compliance, performance, ROI, threat classifier, threat deep dive, zone traffic) transform raw API responses into structured, graded, and ranked datasets ready for rendering.

📊
Visualisation Layer — React + Recharts

Seven navigation sections render live interactive charts (area charts, bar charts, pie charts, world heatmaps) using Recharts and React Simple Maps. Dark/light mode is supported throughout. The entire UI is responsive for desktop and mobile use.

🔒
Security — Credentials Never Leave the Browser

API tokens are stored in browser sessionStorage only. No tokens are sent to or stored on any intermediate server. The backend (Node.js proxy) is only used to bypass CORS restrictions on the CDN vendor APIs — it never logs or persists credentials.
